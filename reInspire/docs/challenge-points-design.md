# Challenge Points: этап с IAP

## Продуктовая модель

Challenge Points являются наградными очками лояльности. Они не продаются
отдельно, не выдаются как оплаченная часть подписки, не передаются между
пользователями, не выводятся в деньги и не имеют срока сгорания.

Активная подписка открывает участие в программе. Очки начисляются только за
подтверждённые действия: выполненный день, серию и завершённый challenge.
Пользователь может направить часть очков на личное обязательство. При успехе
направленные очки возвращаются вместе с наградой; при провале они списываются.

Накопленный порог не меняет цену локально. Он открывает eligibility для заранее
созданного StoreKit promotional offer:

- 500 очков: скидка 25-30% на следующий месяц Pro;
- 1500 очков: скидка 25-30% на переход или продление Pro Annual;
- каждое предложение можно активировать не чаще одного раза за заданный
  сервером период, рекомендуемый интервал 6-12 месяцев.

## Состояния

```text
available -> points_reserved -> active
active -> completed -> points_rewarded
active -> failed_pending_review -> failed -> points_spent
failed_pending_review -> appealed -> manual_review
manual_review -> completed | failed
offer_unlocked -> offer_reserved -> purchased -> points_redeemed
offer_reserved -> cancelled_or_expired -> points_released
```

Все переходы выполняются серверными идемпотентными RPC. Клиент только показывает
состояние. У каждой операции есть уникальный idempotency key.

## Серверные сущности

- `challenge_point_accounts`: пользователь и текущий доступный баланс;
- `challenge_point_ledger`: append-only начисления, резервы, возвраты, списания;
- `point_commitments`: условие, период, направленные очки и состояние;
- `reward_offer_eligibility`: порог, StoreKit offer ID, резерв и срок активации;
- `verification_appeals`: исходный вердикт, комментарий, evidence и решение;
- `promotional_entitlements`: собственные временные права, если награда не
  требует новой транзакции.

RLS разрешает пользователю читать только свои записи. Запись баланса доступна
только SECURITY DEFINER RPC с проверкой `auth.uid()`, фиксированным `search_path`
и отозванным `EXECUTE` у `PUBLIC`/`anon`.

## Покупка предложения

1. Backend атомарно проверяет баланс, cooldown и отсутствие другого резерва.
2. Очки резервируются, но не списываются.
3. Клиент получает подходящий RevenueCat Offering / StoreKit promotional offer.
4. RevenueCat webhook подтверждает реальную транзакцию.
5. Backend списывает резерв ровно один раз по transaction ID.
6. При отмене, ошибке или истечении резерва очки возвращаются.

Для существующего Monthly предложение применяется к следующему периоду. Annual
оформляется как переход внутри одной subscription group. Клиентская отметка об
успехе покупки никогда не является основанием для списания очков.

## Верификация и апелляции

- Сомнительный результат трактуется в пользу пользователя.
- Перед окончательным провалом действует окно апелляции 48 часов.
- Апелляция сохраняет исходное фото и вердикт без перезаписи.
- Денежно значимые спорные случаи попадают в очередь ручного разбора.
- До решения очки остаются зарезервированными.
- Все решения журналируются с actor, причиной и временем.

## Аналитика

- `points_earned`, `points_reserved`, `commitment_started`;
- `commitment_completed`, `commitment_failed`, `commitment_appealed`;
- `reward_offer_unlocked`, `reward_offer_started`;
- `reward_offer_purchased`, `reward_offer_cancelled`;
- баланс до/после, тип источника и версия правил.

## Оценка

- схема, ledger и RPC: 4-6 дней;
- интеграция verification/appeals: 4-6 дней;
- RevenueCat promotional offers и webhook: 3-5 дней;
- iOS UI и аналитика: 5-7 дней;
- QA, sandbox и App Review package: 4-6 дней.

Итого: 20-30 рабочих дней после подтверждения спроса этапом без денег.

## Риски App Review

- нельзя описывать очки как купленную валюту или часть стоимости подписки;
- очки не должны сгорать по времени;
- нельзя обещать деньги, товары или награду от результата других людей;
- цена и скидка должны проходить только через StoreKit;
- условия, списание и апелляция показываются до подтверждения commitment;
- механику нужно подробно объяснить в App Review Notes и дать reviewer account.
